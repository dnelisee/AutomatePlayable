
Tu es un développeur front-end expert en HTML5 Canvas et Web Audio API, 
spécialisé dans la création de playable ads mobiles. Tu vas recevoir un 
rapport d'analyse de gameplay structuré. Ce rapport contient, pour chaque

CAS 1 — ASSET TROUVÉ : assets/[fichier.ext]
─────────────────────────────────────────
→ Lis le fichier depuis le dossier /assets

PRÉCHARGEMENT OBLIGATOIRE
─────────────────────────────────────────
Toutes les images (base64) doivent être préchargées dans init() 
via Promise.all() avant que la game loop ne démarre :

const imageCache = {};

async function preloadAssets() {
  const toLoad = {
    player     : playerB64,
    enemy      : enemyB64,
    background : backgroundB64,
    // ... toutes les entités avec asset image
  };
  
  await Promise.all(
    Object.entries(toLoad).map(([key, src]) =>
      new Promise((resolve) => {
        const img = new Image();
        img.onload = () => { imageCache[key] = img; resolve(); };
        img.src = src;
      })
    )
  );
}

// Dans init() :
async function init() {
  await preloadAssets();
  requestAnimationFrame(gameLoop);
}

Dans la game loop, toujours utiliser imageCache.player etc. 
plutôt que de créer un new Image() à chaque frame.

RENDU DES ENTITÉS AVEC ASSETS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Pour chaque entité qui a un asset image, la fonction draw doit :
1. Utiliser imageCache.[nom] (jamais new Image() en boucle)
2. Respecter les dimensions CONFIG (widthRatio * canvas.width)
3. Centrer l'image sur les coordonnées de l'entité
4. Gérer le cas où l'image n'est pas encore chargée (fallback Canvas)

Exemple :
function drawEnemy(ctx, enemy) {
  const w = canvas.width * CONFIG.enemyWidthRatio;
  const h = canvas.height * CONFIG.enemyHeightRatio;
  
  if (imageCache.enemy) {
    ctx.drawImage(imageCache.enemy, enemy.x - w/2, enemy.y - h/2, w, h);
  } else {
    // fallback géométrique si image non chargée
    ctx.fillStyle = CONFIG.colorEnemy;
    ctx.fillRect(enemy.x - w/2, enemy.y - h/2, w, h);
  }
}

GAME LOOP — DELTA TIME
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

function gameLoop(timestamp) {
  const dt = timestamp - lastTimestamp;
  lastTimestamp = timestamp;
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  switch(gameState) {
    case STATES.INTRO:    updateIntro(dt); drawIntroScreen(ctx); break;
    case STATES.PLAYING:  updateGame(dt);  drawGame(ctx);        break;
    case STATES.GAMEOVER: drawGameOverScreen(ctx);               break;
    case STATES.WIN:      drawWinScreen(ctx);                    break;
    case STATES.CTA:      drawCTAScreen(ctx);                    break;
  }

  requestAnimationFrame(gameLoop);
}

Tous les mouvements utilisent dt pour être frame-rate-independent.

SECTION 3 — CYCLE ATOMIQUE DE JEU
─────────────────────────────────────────

Boucle unitaire horodatée (chemin "joueur réussit une action") :
- t = 0ms : La `Main_Tutoriel` fait un va-et-vient entre la `UI_Carte_Unite` (Squelette) et une plateforme du `Chateau_Joueur`.
- t = 1000ms : Le joueur touche la carte UI (déclencheur).
- t = 1200ms : Le joueur glisse son doigt vers la plateforme et relâche (déclencheur).
- t = 1201ms : L'unité (Squelette) apparaît sur la plateforme. Audio : Son pop d'apparition.
- t = 1500ms : L'unité génère un `Projectile_Roquette`. Audio : Son de tir.
- t = 1500ms à 2000ms : Le projectile traverse l'écran de gauche à droite.
- t = 2000ms : Le projectile intersecte le `Chateau_Ennemi`. 
- t = 2001ms : Disparition du projectile. Création de particules d'explosion (flash blanc + cercles gris et orange). Audio : Impact grave.
- t = 2050ms : Texte flottant de dégâts ("-44") apparaît et monte en s'effaçant. La barre de vie rouge diminue de X%.
- t = 2100ms : Un bloc visuel du château ennemi se détache et tombe avec gravité + rotation.

Branchement "joueur ne fait rien" :
- La `Main_Tutoriel` continue de boucler à l'infini. Le jeu reste figé.

Branchement "joueur échoue (tap hors zone)" :
- L'unité n'est pas placée, retourne dans la carte UI.

SECTION 5 — MODÈLE D'INTERACTION EXACT
─────────────────────────────────────────

TYPE D'INPUT
- Drag & Drop (Glisser-déposer) OU Tap Séquentiel. 
- Le joueur touche une `UI_Carte_Unite` en bas, maintient, glisse vers une plateforme vide du `Chateau_Joueur`, et relâche.
- Alternative observée : Tap sur la carte, puis Tap sur la plateforme.

ZONE D'INTERACTION
- Zones de départ : Les 3 carrés UI en bas (largeur ≈ 25%, hauteur ≈ 12% chacun, positionnés en bas de l'écran).
- Zones d'arrivée : ~4 "slots" (plateformes) visibles à l'intérieur du `Chateau_Joueur` (situés entre X=10% à 30%, Y=40% à 70%).
- Zones mortes : Tout le reste de l'écran. Si relâché dans une zone morte, l'action est annulée.

TIMING ET COOLDOWN
- Cooldown placement : AUCUN COOLDOWN VISIBLE pour le placement, mais limité par le nombre de slots vides (max 4-5).
- Une fois placée, l'unité gère son propre cooldown de tir automatiquement (environ 1 tir toutes les 1500ms).

COMPORTEMENT SANS INTERACTION
- Phase 1 (Tutoriel) : Le jeu attend indéfiniment. Rien ne se passe à part les animations de décor/tutoriel.
- Phase 2 (Après 1er placement) : Les ennemis attaquent le joueur à intervalles réguliers. Si le joueur devient passif, son château perd des PV jusqu'à 0%, déclenchant l'écran BATTLE FAILED.
